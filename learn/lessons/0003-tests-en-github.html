Lección 3: Tus tests corren solos en GitHub

Integración continua: cada push, pytest, sin que tú hagas nada.

Por qué

Hoy pytest corre cuando te acuerdas de correrlo, en tu máquina, con tu .venv. Eso da tres problemas:

  1. Te olvidas de correr pytest antes de un push y subes código roto sin saberlo.
  2. "En mi máquina funciona": tu .venv tiene cosas instaladas que el repo no declara, y nadie más (ni tú en otro PC) puede correrlo.
  3. No hay rastro: nadie sabe si el commit ce3d68c pasaba los tests o no.

GitHub Actions arregla las tres. Cada vez que haces push, GitHub arranca una máquina limpia, clona tu repo, instala lo que dice pyproject.toml, corre pytest, y pone un tick verde o una cruz roja al lado del commit.

Qué es un workflow

Un workflow es un fichero de texto en .github/workflows/ que le dice a GitHub qué hacer y cuándo.

Está en YAML: un formato de clave: valor donde la indentación (dos espacios) marca qué va dentro de qué, y las listas van con -. Es como el JSON que ya conoces, pero sin llaves ni comillas, y con la indentación haciendo el trabajo.

El fichero

.github/workflows/tests.yml

name: tests

on: [push, pull_request]

jobs:
  pytest:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -e ".[dev]"
      - run: python -m pytest
LíneaQué hace
name: testsNombre que verás en GitHub.
on: [push, pull_request]Cuándo corre: en cada push y en cada pull request.
jobs: / pytest:Un trabajo, llamado pytest. Podría haber varios.
runs-on: ubuntu-latestEn qué máquina: una Linux limpia que GitHub crea y destruye para cada run.
steps:Los pasos, en orden. Cada - es uno.
uses: actions/checkout@v4Acción prehecha: clona tu repo en esa máquina.
uses: actions/setup-python@v5 + python-version: "3.12"Acción prehecha: instala Python 3.12 (la misma que usas tú).
run: pip install -e ".[dev]"Comando de terminal: instala tu proyecto y pytest, según pyproject.toml. El [dev] es la lista dev = ["pytest"] de ese fichero.
run: python -m pytestEl mismo comando que corres tú.

uses = usar una acción que otro ya escribió. run = un comando de terminal normal. Todo lo demás es estructura.

Dónde se ve

En tu repo en GitHub, pestaña Actions (github.com/Magomin/re-track/actions). Cada push aparece como un run con el mensaje del commit.

  • Verde = todo pasó.
  • Rojo = algo falló. Entras, abres el paso python -m pytest, y ves la misma salida de pytest que ves en tu terminal, con su línea E.

También verás un tick o una cruz al lado de cada commit en la lista de commits.

Comprueba

1. ¿Cuándo corre el workflow?

on: [push, pull_request]. Correr pytest en tu máquina no toca GitHub.

2. runs-on: ubuntu-latest significa...

GitHub crea una máquina Linux limpia para cada run. Tu PC no interviene.

3. CI en rojo y tu máquina en verde. Lo primero es...

El log tiene la salida de pytest de la máquina limpia. Casi siempre es algo que tu .venv tenía y el repo no declara.

Ahora en Re-track

Esta lección son tres commits, porque cada push es un experimento.

  1. Crea la carpeta .github/workflows/ en la raíz del repo (dos carpetas, la primera con punto delante) y dentro el fichero tests.yml con el contenido de arriba, tal cual. Cuidado con la indentación: dos espacios, nunca tabulador.
  2. Commit y push: 
    git add -A
git commit -m "Add GitHub Actions workflow: pytest on push"
git push
  3. Abre github.com/Magomin/re-track/actions. Espera a que el run termine (un minuto). Tiene que estar en verde. Si está en rojo, ábrelo, lee el log del paso que falló y pégaselo a Claude.
  4. Rómpelo a propósito. En tests/test_live.py, cambia 123.0 por 999 en el assert de test_parse_success. Commit "Break a test on purpose", push. Vuelve a Actions: rojo. Entra en el run, abre el paso python -m pytest, busca la línea E. Es la misma que viste en la lección 1, pero en una máquina que no es la tuya.
  5. Arréglalo. Vuelve a poner 123.0. Commit "Fix the test", push. Verde otra vez.
  6. Opcional: badge en el README. Añade esta línea debajo del título de README.md: 
    ![tests](https://github.com/Magomin/re-track/actions/workflows/tests.yml/badge.svg)
    Commit y push. Verás el estado de los tests en la portada del repo.

Pega a Claude el enlace del run verde final.
