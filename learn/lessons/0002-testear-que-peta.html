Lección 2: Testear que una función peta

Cuando el error ES el comportamiento correcto.

Recordatorio: raise

raise para el programa a propósito, con un mensaje que dice la causa real. En el proyecto, parse() hace justo esto cuando Ableton contesta status: "error".

Escríbelo tú en la consola de Python:

>>> def dividir(a, b):
...     if b == 0:
...         raise ValueError("entre cero no")
...     return a / b
...
>>> dividir(10, 2)
5.0
>>> dividir(10, 0)
Traceback (most recent call last):
  ...
ValueError: entre cero no

Petar aquí no es un fallo. Es lo que queremos: dividir detecta el problema y lo dice.

El problema

Quieres un test que compruebe que dividir(10, 0) peta. Si escribes esto:

def test_dividir_entre_cero():
    dividir(10, 0)

el test peta con ValueError, y pytest lo marca como FAILED. Pero petar era lo correcto.

Necesitas decirle a pytest: "aquí espero un error, y si llega, el test pasa".

pytest.raises

import pytest


def test_dividir_entre_cero():
    with pytest.raises(ValueError):
        dividir(10, 0)
  • import pytest arriba del fichero.
  • with pytest.raises(ValueError): abre un bloque que significa "dentro de esto espero un ValueError".
  • La llamada que debe petar va dentro, indentada. Si el error llega, el test pasa. Si no llega, el test falla.

Es el mismo with que usas con el socket en send(): un bloque con entrada y salida. Aquí, a la salida, pytest comprueba si hubo error.

Las dos formas de fallar

  1. La función NO peta. pytest te enseña: 
    Failed: DID NOT RAISE <class 'ValueError'>
    Significa: esperabas un error y no llegó.
  2. Peta con OTRO tipo, por ejemplo TypeError. El test falla con el traceback de ese otro error, porque pytest.raises(ValueError) solo atrapa ValueError.

Si ves un traceback que no esperabas, el tipo de error en el raise no coincide con el del test.

Comprobar el mensaje (opcional)

with pytest.raises(ValueError, match="cero"):
    dividir(10, 0)

Además del tipo, comprueba que el mensaje contiene "cero". Útil cuando una función puede petar por varias razones y quieres saber cuál. Hoy no hace falta.

Comprueba

1. ¿Qué pasa si la función dentro de pytest.raises(ValueError) no peta?

Le dijiste a pytest que esperabas un error. Si no llega, falla con DID NOT RAISE.

2. ¿Dónde va la llamada que debe petar?

pytest.raises solo vigila lo que pasa dentro de su bloque. Fuera, el error rompe el test como siempre.

3. DID NOT RAISE significa...

Literal: "no lanzó". El bloque terminó sin error. Si petara con otro tipo, verías el traceback de ese otro error.

{"status": "error", "result": {}, "message": "Unknown command: no_existe"}
  1. En tests/test_live.py, añade import pytest arriba, debajo del import de parse.
